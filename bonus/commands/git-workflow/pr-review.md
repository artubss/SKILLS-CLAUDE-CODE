# Revisão de PR

## Tarefa 1: Revisão do Product Manager

**Objetivo**: Avaliar sob perspectiva de gerenciamento de produto, focando em:
- **Valor de Negócio**: Este PR avança claramente nossos objetivos principais de produto e entrega ROI imediato?
- **Experiência do Usuário**: A mudança é intuitiva e agradável para os usuários agora? Se não, faça correções imediatamente.
- **Alinhamento Estratégico**: O PR se alinha com objetivos estratégicos atuais (e de longo prazo, ou seja, agora)?

**Ação**: Forneça diretrizes claras sobre como garantir máximo impacto para usuário e negócio. Todas as sugestões "futuras" devem ser implementadas agora.

---

## Tarefa 2: Revisão do Developer

**Objetivo**: Avaliar o código minuciosamente sob perspectiva de engenheiro sênior líder:
1. **Qualidade de Código & Manutenibilidade**: O código está estruturado para legibilidade e fácil manutenção? Se não, refatore agora.
2. **Performance & Escalabilidade**: Essas mudanças funcionarão eficientemente em escala? Se não, otimize imediatamente.
3. **Melhores Práticas & Padrões**: Observe qualquer desvio de padrões de código e corrija agora.

**Ação**: Deixe um comentário de revisão conciso mas completo, garantindo que todas as melhorias aconteçam imediatamente—sem adiamentos.

---

## Tarefa 3: Revisão do Quality Engineer

**Objetivo**: Verificar qualidade geral, estratégia de testes e confiabilidade da solução:
1. **Cobertura de Testes**: Há testes suficientes (unitários, integração, E2E)? Se não, adicione agora.
2. **Bugs Potenciais & Casos Extremos**: Todos os casos extremos foram considerados? Se não, endereçe imediatamente.
3. **Risco de Regressão**: Confirme que mudanças não comprometem funcionalidade existente. Se risco for identificado, mitigue agora com verificações ou testes adicionais.

**Ação**: Forneça avaliação QA detalhada, insistindo que qualquer melhoria "futura" seja concluída agora.

---

## Tarefa 4: Revisão do Security Engineer

**Objetivo**: Garantir práticas robustas de segurança e conformidade:
1. **Vulnerabilidades**: Essas mudanças poderiam introduzir vulnerabilidades de segurança? Se sim, corrija imediatamente.
2. **Manipulação de Dados**: Estamos protegendo adequadamente dados sensíveis (ex: encriptação, sanitização)? Endereçe todas as lacunas agora.
3. **Conformidade**: Confirme alinhamento com padrões relevantes de segurança ou privacidade (ex: OWASP, GDPR, HIPAA). Implemente requisitos faltantes imediatamente.

**Ação**: Forneça avaliação de segurança. Qualquer correção recomendada tipicamente agendada para "depois" deve ser endereçada agora.

---

## Tarefa 5: Revisão do DevOps

**Objetivo**: Avaliar considerações de build, deployment e monitoramento:
1. **Pipeline CI/CD**: Valide que o PR integra suavemente com processos existentes de build/teste/deploy. Se não, corrija agora.
2. **Infraestrutura & Configuração**: Verifique se mudanças de código requerem atualizações imediatas de infraestrutura ou configs.
3. **Monitoramento & Alertas**: Identifique novas necessidades de monitoramento ou melhorias potenciais e implemente imediatamente.

**Ação**: Forneça revisão focada em DevOps, insistindo que qualquer melhoria ou ajuste seja executado agora.

---

## Tarefa 6: Revisão do UI/UX Designer

**Objetivo**: Garantir design otimizado e centrado no usuário:
1. **Consistência Visual**: Confirme aderência a diretrizes de marca/design. Se não, ajuste agora.
2. **Usabilidade & Acessibilidade**: Valide que UI é intuitiva e compatível com padrões de acessibilidade. Faça qualquer correção imediatamente.
3. **Fluxo de Interação**: Avalie se o fluxo do usuário é perfeito. Se fricção existir, refine agora.

**Ação**: Forneça avaliação UI/UX detalhada. Qualquer melhoria tipicamente marcada para "depois" deve ser feita imediatamente.
