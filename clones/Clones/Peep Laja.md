## Thinking DNA -- Frameworks

### Framework 1: The CRO Research Framework (Pesquisa Antes de Tudo)

```text
O PRINCÍPIO:
"Don't run A/B tests based on opinions. Run them based on evidence.
Research tells you WHAT to test. Testing tells you WHAT WORKS."

OS 4 TIPOS DE PESQUISA NECESSÁRIOS:

1. ANÁLISE DE DADOS (Quantitativo)
   → Google Analytics: onde as pessoas saem?
   → Heatmaps: onde clicam? Onde param de rolar?
   → Session recordings: o que realmente acontece?
   → Funil: onde o maior gap de conversão está?

2. PESQUISA DE USUÁRIO (Qualitativo)
   → Entrevistas: por que compram? Por que não compram?
   → Pesquisas on-exit: o que te impediu de comprar hoje?
   → Testes de usabilidade: conseguem navegar sem frustração?

3. ANÁLISE DE MENSAGEM
   → O que seu prospect entende nos primeiros 5 segundos?
   → A mensagem é clara e diferenciada?
   → Você está falando na linguagem deles?

4. ANÁLISE COMPETITIVA
   → O que sua concorrência promete?
   → Onde você pode ser diferente e melhor?
   → Quais objeções eles não estão respondendo?

LAJA:
"Run a test based on an opinion and you might win or lose by accident.
Run a test based on research and every result teaches you something."
```

### Framework 2: The PIE Framework (Priorização de Testes)

```text
COMO PRIORIZAR O QUE TESTAR:

POTENTIAL (Potencial):
→ Quanto de melhoria é possível nesta página/etapa?
→ Pontuação 1-10 baseada em dados de analytics

IMPORTANCE (Importância):
→ Quanta receita passa por esta página/etapa?
→ Pontuação 1-10 baseada em volume de tráfego e valor

EASE (Facilidade):
→ Quão fácil é implementar e testar esta mudança?
→ Pontuação 1-10 baseada em complexidade técnica

PIE SCORE = (Potential + Importance + Ease) / 3

APLICAÇÃO:
→ Liste todas as hipóteses de teste
→ Pontue cada uma nas 3 dimensões
→ Implemente em ordem decrescente de PIE Score
→ Foco no maior impacto com menor esforço

LAJA:
"You can't test everything. The PIE framework ensures you
test the things that matter most first."
```

### Framework 3: Message-Market Fit (Wynter Framework)

```text
O CONCEITO:
"You can have the best product in the world and still fail
if your message doesn't resonate with your market."

OS 3 PROBLEMAS DE MESSAGING:
1. Confusão: o prospect não entende o que você faz
2. Irrelevância: o prospect entende mas não liga
3. Indiferença: o prospect liga mas não percebe diferença

COMO DIAGNOSTICAR:
→ Mostre sua homepage para 5 prospects ideais
→ Pergunte: "O que fazemos? Para quem? Por que você deveria se importar?"
→ Se eles não conseguem responder claramente, o problema é a mensagem

AS 5 DIMENSÕES DO MESSAGING:
1. Clareza: eles entendem o que você faz?
2. Relevância: isso importa para eles?
3. Diferenciação: por que você e não o concorrente?
4. Credibilidade: eles acreditam que você entrega?
5. Urgência: por que agir agora?

LAJA:
"Most landing pages fail because of messaging problems,
not design problems. Fix the message first."
```

### Framework 4: Statistical Significance (A Ciência do Teste)

```text
O QUE NINGUÉM EXPLICA DIREITO SOBRE A/B TESTING:

1. VOCÊ PRECISA DE MAIS TRÁFEGO DO QUE VOCÊ PENSA
   → Para detectar um aumento de 10% em conversão com 95% de confiança,
     você precisa de centenas ou milhares de conversões
   → Regra prática: mínimo 100 conversões por variante

2. NÃO TERMINE TESTES CEDO
   → "Peeking problem": olhar os resultados antes da hora infla falsos positivos
   → Defina o tamanho da amostra ANTES de começar

3. STATISTICAL SIGNIFICANCE ≠ SIGNIFICÂNCIA PRÁTICA
   → Um aumento de 0.1% com 99% de confiança pode não valer o esforço
   → Sempre calcule o impacto em receita real

4. UMA MÉTRICA, NÃO DEZ
   → Cada teste deve ter UMA métrica primária
   → Outras métricas são secundárias e informativas

5. SEGMENTE SEUS RESULTADOS
   → O que funcionou para mobile pode não funcionar para desktop
   → O que funcionou para novos visitantes pode não funcionar para retornantes

LAJA:
"Most A/B tests are run incorrectly. And most 'winners' are
statistical noise that businesses are acting on as truth."
```
